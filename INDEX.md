# INDEX.md — RAGI Baking Academy Apps — UI Design

> Map for scoped loading. Always load `_foundation/*`; then open the ONE domain you're working in.
> Regenerate after structural changes: `python scaffold_icm.py lint --path . --fix`.

## Root
- `CLAUDE.md` — global orientation — read first every session
- `DECISIONS.md` — decision memory (Locked / Proposed / Foundation Challenges)

## _foundation/ (the law — load every session)
- `_foundation/brand-and-tokens.md` — Official brand colours and fonts, the design direction, verified contrast pairs, and the rules for using colour.
- `_foundation/content-language.md` — Bahasa Indonesia rules, number formats, and the fixed UI strings taken verbatim from the PRD.
- `_foundation/glossary.md` — Shared vocabulary: English terms and the Indonesian words that appear in the UI.
- `_foundation/iconography.md` — Icon pack decision (Lucide), verified facts, known gaps, and the rules for using icons.
- `_foundation/product-brief.md` — What the app is, who uses it, Phase 1 scope, the out-of-scope guard, and the client inputs still owed.
- `_foundation/screen-inventory.md` — S1–S19 with roles, stories and states, plus the overlays the stories imply (O1–O12) and the PDF layout.
- `_foundation/ui-rules.md` — Business rules and accessibility rules that constrain every screen: grams, verdicts, roles, states and formats.
- `_foundation/workflow.md` — The 4-stage design pipeline: inputs, outputs, gates, HTML-prototype rules and the review protocol.

## 01_Requirements_Flows/
- `01_Requirements_Flows/context.md` — Stage 1 of 4. Turn the PRD into design-ready briefs and flows.
- `01_Requirements_Flows/reference/navigation-map.md` — Load when placing a screen in the app: tabs, flows, global states (D-016, D-017).
- `01_Requirements_Flows/reference/screen-briefs.md` — Load when building any screen or overlay: what it shows, does and which states it needs (S1 to S19, O1 to O12).
- `01_Requirements_Flows/reference/coverage-matrix.md` — Load to check a PRD story has a screen.

## 02_Design_System/
- `02_Design_System/context.md` — Stage 2 of 4. Build the tokens, the icon map and the components every screen uses.
- `02_Design_System/reference/icon-map.md` — Load when choosing or placing an icon in stage 2 or 3: PRD concept to Lucide icon name, each verified to exist.
- `02_Design_System/reference/tokens.json` — Source of truth for colour, type, spacing, radius, elevation, motion. `tokens.css` is generated by `build_assets.py`.
- `02_Design_System/reference/components.md` — Load when building a screen: every component, its states, tokens and stories.
- `02_Design_System/reference/components.html` — Living component sheet (serve over http; needs fonts and scripts beside it).
- `02_Design_System/reference/logic.js` — Number format, dough metrics, scaling, compare; `logic.test.js` holds the PRD scenarios.
- `02_Design_System/reference/contrast-report.md` — Generated AA check of every token pair.

## 03_Screens/
- `03_Screens/context.md` — Stage 3 of 4. Design every screen and state as a clickable HTML prototype.
- `03_Screens/working/README.md` — Load to run, use and review the prototype: how to start it, URL parameters, file map, checks done, gaps.
- `03_Screens/working/board.json` — Status of every screen and overlay (structured data).

## 04_Review_Handoff/
- `04_Review_Handoff/context.md` — Stage 4 of 4. Get RAGI's approval, then package the design for developers.
